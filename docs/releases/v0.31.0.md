sigma 0.31.0 audits every plugin prompt against the Opus 5.5 prompting guide and fixes what was dated.

## Changed
- **`/craft`** says in one line what each stage will do, gives a one-line result after it, and ends with a short recap.
- **`/research`** gives its parallel lanes a time budget (about 300s by default, 600s for web, 900s for deep) and shows `elapsed Ns / Bs` in each brief. When the budget runs out it synthesizes what came back and names any lane that did not finish. The prompt uses plain case instead of stacked capitals and finds the gpt researcher through `${CLAUDE_PLUGIN_ROOT}`.
- **`/verify`** hands the check to the read-only `sigma-verifier` agent, so maker ≠ checker also holds outside `/loop`. The verifier gets the `Skill` tool so it can find domain verifiers from any repo.
- **`/implement-task`** swaps the seven-step reuse ladder for one "reuse first" rule. The `/spec` example scenarios are now labeled illustrative.
- **`/grill`, `/grill-loop`, `/sigma-learn-lesson` and skills** no longer mention code that was removed (`_verdict_pass`, `cli/loop.py`) or explain past versions. The lesson-matching prefixes now include `loop failed:` and `e2e failed:`.
- **Domain guides:**
  - prompt-engineering teaches structured outputs (`output_config.format`) instead of "respond ONLY with JSON"
  - tool-definition covers `strict: true` and the forced `tool_choice` 400
  - harness-design stops recommending partial-history summarizing, which invalidates thinking blocks
  - the LLM verifier flags request params that return 400 on Opus 5.5
- **Research:** the claude lane now allows WebSearch and WebFetch in `--web`/`--deep` mode, so it can actually cite what the brief asks it to look up.

## Verification
- 665 pytest tests pass and ruff is clean. `sigma docs-check --check` passes.
- `claude plugin validate` passes for the manifest, agents, commands and skills.
